## TLA2528 ADC 配置与调试笔记

本文记录本项目中使用 TLA2528（8 通道 12bit I2C ADC）读取 NTC 的**寄存器配置步骤、查阅手册的方法，以及本次调试过程中的经验总结**，便于后续复用和排错。

---

## 一、I2C 地址与基本概念

- **I2C 地址确认**
  - 通过手册 Table 2（ADDR 引脚电阻配置表）确认器件的 7bit 地址，例如本项目为 `0x10`。
  - STM32 HAL 使用 8bit 地址：
    - 写地址：`TLA2528_I2C_WRITE_ADDR = (TLA2528_I2C_ADDR << 1)` → `0x20`
    - 读地址：`TLA2528_I2C_READ_ADDR  = (TLA2528_I2C_ADDR << 1) | 1` → `0x21`

- **寄存器访问方式（关键点）**
  - TLA2528 的寄存器不是“直接地址 + 数据”，而是先发 **Opcode + Register Address**：
    - 单寄存器写：`0x08, reg_addr, data`
    - 单寄存器读：`0x10, reg_addr`，然后再发一个读帧取 1 字节数据
  - 所有 HAL I2C 读写操作都需要遵守这个命令格式，否则会出现“寄存器读写失败或读到 0”的现象。

- **ADC 转换结果不是寄存器，而是“数据帧”**
  - 手册 7.3.9 / 图 6：ADC 转换后的结果通过 I2C 读帧输出：
    - 第 1 字节：`D11..D4`
    - 第 2 字节：高 4 位 `D3..D0`，低 4 位为状态或保留位
  - 正确组合方式：
    \[
      \text{adc\_value} = (\text{byte0} << 4) | ((\text{byte1} >> 4) \& 0x0F)
    \]
  - 不要尝试去读“某个寄存器（比如 0x04/0x05）当成结果寄存器”，否则会一直读到 0。

## 二、配置 ADC 寄存器的推荐步骤

### 1. GENERAL\_CFG（0x01）

- 目的：基础控制，包括“强制所有通道为模拟输入”和“单次转换触发”。
- 关键位：
  - `CH_RST`（bit2）：强制所有通道为模拟输入（AIN），忽略 GPIO 配置。
  - `CNVST`（bit3）：写 1 触发一次 ADC 转换（读回始终为 0）。
- 在初始化中的使用：
  - 上电配置阶段：
    - 写 `GENERAL_CFG = 0x04`（仅设置 `CH_RST=1`），确保所有通道都是 ADC 输入。
  - 触发单次转换：
    - 每次采样前调用：`GENERAL_CFG = 0x08`（`CNVST=1`），启动一次转换。

### 2. DATA\_CFG（0x02）

- 目的：控制输出数据格式（是否追加通道 ID、是否输出固定模式数据）。
- 常用位：
  - `FIX_PAT`（bit7）：置 1 时 ADC 始终输出固定码 `0xA5A`，仅用于调试通信。
  - `APPEND_STATUS[1:0]`（bit5..4）：是否在结果后附加 4bit 通道 ID/状态。
- 本工程配置：
  - 写 `DATA_CFG = 0x00`：
    - 不使用固定模式；
    - 不附加通道 ID，读取逻辑最简单。

### 3. OSR\_CFG（0x03）

- 目的：控制过采样（平均滤波）倍率。
- `OSR[2:0]`：采样点数（1、2、4、8、16、32、64、128），过采样输出为 16bit。
- 本工程初期调试：
  - 写 `OSR_CFG = 0x00`：**禁用过采样**，只看最基础的 12bit 原始数据，方便排错。

### 4. OPMODE\_CFG（0x04）

- 目的：选择内部振荡源和采样速率。
- 关键位：
  - `OSC_SEL`（bit4）：0=高速振荡器，1=低功耗模式。
  - `CLK_DIV[3:0]`（bit3..0）：采样周期分频，结合手册表 4 计算采样频率。
- 本工程配置：
  - 写 `OPMODE_CFG = 0x00`：高速振荡器 + 最快采样频率，以保证转换完成时间远小于我们设置的 `HAL_Delay`。

### 5. PIN\_CFG（0x05）及 GPIO 相关寄存器

- 默认所有通道上电时即为 **模拟输入**，对单纯做 ADC 采样来说可以不改。
- 若曾经配置过 GPIO 功能，需要：
  - 通过 `GENERAL_CFG.CH_RST=1` 强制所有通道恢复为模拟输入。
  - 或按手册表 3 手动清除 `PIN_CFG` / `GPIO_CFG` 的对应位。

### 6. SEQUENCE\_CFG（0x10）、CHANNEL\_SEL（0x11）、AUTO\_SEQ\_CHSEL（0x12）

- 本工程使用最简单的 **手动模式**：
  - `SEQUENCE_CFG.SEQ_MODE = 0b00`（手动模式）
  - `CHANNEL_SEL.MANUAL_CHID[3:0]` 写入要采样的通道号（0–7）。
- 采样单个通道的推荐流程：
  1. 写 `CHANNEL_SEL = ch`（`ch` 为通道号 0–7）；
  2. 调用 `TriggerConversion`：`GENERAL_CFG.CNVST=1`；
  3. 等待 `tCONV`（本工程使用 `HAL_Delay(1)`，毫秒级足够）；
  4. 通过 2 字节数据帧读取 ADC 结果。

## 三、阅读 & 使用手册的步骤

1. **从目录入手，锁定三个关键章节：**
   - `7 Detailed Description`：功能框图、ADC 通道配置、GPIO 等；
   - `7.5 Programming`：I2C 命令帧格式（opcode、寄存器读写）；
   - `7.6 TLA2528 Registers`：完整寄存器表和每个寄存器的位定义。

2. **先看寄存器总表（Table 8）和寄存器地址**
   - 确认有哪些关键寄存器、各自地址、上电默认值和用途。
   - 结合工程里现有宏定义（如 `TLA2528_REG_GENERAL_CFG`）比对是否一致。

3. **重点看“编程章节（7.5）”的 I2C 帧格式**
   - 了解：**寄存器访问必须通过 opcode**，而不是简单的“地址 + 数据”。
   - 根据图 10 / 图 12 等，把单寄存器读写的时序翻译为：
     - 写：`0x08 + reg_addr + data`；
     - 读：`0x10 + reg_addr`，然后再发一个读帧。

4. **阅读“输出数据格式（7.3.9）和图 6”**
   - 搞清楚：ADC 转换结果是通过数据帧读出，不是普通寄存器。
   - 搞清楚：`byte0`、`byte1` 各自 bit 的含义（高 12 位为有效数据）。

5. **查看“功能模式（7.4）”**
   - 区分“手动模式”和“自动序列模式”；
   - 本项目选择手动模式，简化逻辑。

6. **最后再回头看 ADC 转换特性和时序**
   - `tCONV`、`tSTRETCH` 等参数，只要我们软件延时远大于这些值，就可以先不用太精确。

## 四、本次调试过程中的经验总结

### 1. 先验证 I2C 硬件链路

- 使用 HAL 提供的 `HAL_I2C_IsDeviceReady`：
  - 成功说明地址、电源、上拉、电气连接基本无误。
- 若失败，要先检查：
  - I2C 实例与引脚映射（本工程使用 I2C2，PB10/PB11）；
  - 上拉电阻、线序、焊接等硬件问题；
  - 7bit 地址与 ADDR 引脚电阻配置是否匹配。

### 2. 明确寄存器访问协议（Opcode）

- 一开始如果直接 `HAL_I2C_Master_Transmit(... &reg_addr)`，往往会读出 0 或 NACK。
- 按手册 7.5 实现 `WriteReg` / `ReadReg`，将“opcode + reg\_addr (+ data)”打包成 tx 缓冲区，是成功读写寄存器的前提。

### 3. 区分“配置寄存器”和“数据帧”

- 本次最关键的坑：一开始尝试读取 0x04/0x05 当做“ADC 结果寄存器”，导致所有通道读到都是 0。
- 正确方式：
  - **配置寄存器**（`GENERAL_CFG`、`DATA_CFG`、`SEQUENCE_CFG` 等）通过 opcode + 地址访问；
  - **采样结果**通过专用 I2C 读帧输出，不在寄存器表中。

### 4. 触发转换时不要误用 RST 位

- `GENERAL_CFG` 中：
  - bit0：`RST`（写 1 会软件复位所有寄存器）；
  - bit3：`CNVST`（写 1 启动一次转换）。
- 调试时一度将 `0x01` 认为是“启动转换”，结果每次都在复位设备，后续数据当然也是异常。

### 5. 设计一个“分步骤”的调试函数很重要

本工程的 `I2C_DebugTest()` 分成多个 Step：

- Step 1：`IsDeviceReady` 确认设备在线；
- Step 2：读 `SYSTEM_STATUS` 等关键寄存器；
- Step 3：扫描 0x00–0x1F 所有寄存器，确认配置是否按预期变化；
- Step 4：检查/设置 PIN 为 ADC 模式；
- Step 5：触发一次转换；
- Step 6：直接读取数据帧，打印原始两字节与 12bit 解码结果。

这种分段打印的方式，可以快速定位“出问题的是哪一步”：

- 如果 Step 1 失败，是总线/地址问题；
- 如果 Step 1 成功但 Step 2 失败，是寄存器访问协议问题；
- 如果寄存器都 OK 但 Step 6 数据全 0，说明触发/取数方式不对；
- 如果 Step 6 的 raw 值合理，再检查硬件分压与 NTC 参数即可。

### 6. 用工程实际电路反推 NTC 电阻，验证是否合理

- 结合实际电路：`VCC → 4.7k → 节点 → NTC → GND`，用 ADC 码值还原电压和电阻：
  - \(V_{\text{NTC}} = \frac{\text{raw}}{4095} \times 3.3\text{V}\)
  - \(R_{\text{NTC}} = \frac{4.7\text{kΩ} \cdot V_{\text{NTC}}}{3.3\text{V} - V_{\text{NTC}}}\)
- 例如 raw≈2990，计算出 \(R_{\text{NTC}} \approx 11\text{kΩ}\)，和 25℃ 10k NTC 在室温附近的实际电阻值非常接近，说明 ADC、分压和 NTC 都工作正常。

## 五、后续扩展建议

- 如需提高抗噪声能力，可在保证刷新率的前提下 **启用 OSR 过采样**，并切换到 16bit 结果读取路径。
- 要扫描多个通道时，可以考虑使用 **自动序列模式（Auto-Sequence）**，通过配置 `AUTO_SEQ_CHSEL` 和 `SEQUENCE_CFG.SEQ_MODE/SEQ_START` 来由硬件轮询通道，简化软件逻辑。
- 在产品代码中保留 `I2C_DebugTest()` 或简化版，有助于现场快速判断是“总线/器件问题”还是“上层逻辑问题”。
